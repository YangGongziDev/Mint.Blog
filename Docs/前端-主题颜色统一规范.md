# Mint 全系统主题规范

## 目的

本文档用于统一 `Mint` 系统的日间和暗色主题规则，适用于当前已有的 `Blog`、`System`，以及未来扩展的 `MES` 等业务域。

本规范只做一件事：

- 让整个系统按照同一套主题结构长期演进，而不是每个模块各自定义颜色。

适用范围：

- `Mint.Blog.Vue/src/views`
- `Mint.Blog.Vue/src/components`
- `Mint.Blog.Vue/src/layouts`
- `Mint.Blog.Vue/src/theme`
- `Mint.Blog.Web.Nuxt/app/pages`
- `Mint.Blog.Web.Nuxt/app/components`
- `Mint.Blog.Web.Nuxt/app/assets/css`
- `Mint.Blog.Web.Nuxt/app/composables/useSitePreferences.ts`
- 后续新增的 `MES` 或其他业务域前端模块

## 一、主题总决策

全系统主题统一按照以下结论执行：

1. 不再为单个模块单独定义一整套主题，而是建立一套全系统可扩展主题规范。
2. 主题拆分为 `基础主题层` 和 `业务域强调层`。
3. `Blog`、`System`、未来 `MES` 共用同一套基础主题。
4. 不同业务域只补自己的强调色，不重定义整套底色和语义色。
5. 暗色模式下，整个系统尽量统一为蓝灰基调，避免每个模块各用一套高饱和主色。

这是本文档的最高原则。后续所有页面、组件、主题 token、样式变量，都必须服从这五条。

## 二、主题结构

### 1. 基础主题层

基础主题层由全系统共享，负责：

- 页面背景
- 容器背景
- 浮层背景
- 标题文字
- 正文文字
- 弱化文字
- 常规边框
- 阴影
- 通用语义色

这一层不区分 `Blog`、`System`、`MES`。

### 2. 业务域强调层

业务域强调层只负责模块辨识度，主要影响：

- 主按钮
- 激活态
- 标签强调色
- 页面局部装饰
- 模块标题强调色
- 图表主色

这一层才区分 `Blog`、`System`、`MES`。

### 3. 依赖顺序

实际使用时，按下面顺序取值：

1. 先取基础主题层
2. 再取全系统语义色
3. 最后按业务域补强调色
4. 支持个性化主色的 Nuxt 前台，仅在品牌强调部分应用用户偏好或该前台默认值，具体见第五节；不覆盖基础主题或语义色。

禁止反过来做，即：

- 不要先定业务域色，再倒推页面背景和正文色
- 不要让某个业务域重写整套基础主题

暗色强调色：

- `brand-soft`: `rgba(83, 157, 253, 0.10)`

规则：

- 以上色板是 `Blog` 的系统推荐配色：日间保留薄荷绿，暗色切换到蓝色，不再把绿色作为默认主视觉色。
- Nuxt 前台采用下述用户个性化主色规则；这项例外不改变 Vue 前台、后台及其他业务域的推荐配色。

#### Nuxt 前台用户个性化主色

适用于 `Mint.Blog.Web.Nuxt` 顶部菜单「设置」抽屉中的主题主色设置。

**默认值与快捷预设**

Nuxt 前台当前默认主色为 `#ee2b7f`，不是全系统 `Blog` 推荐色板的替代值。用户既可以点击预设色块，也可以通过调色盘自定义颜色。

| 预设名称 | 颜色值 |
| --- | --- |
| 默认粉 | `#ee2b7f` |
| 薄荷绿 | `#3ecf9a` |
| 晴空蓝 | `#539dfd` |
| 靛蓝 | `#4f7cff` |
| 紫罗兰 | `#a543e6` |
| 琥珀橙 | `#f5a630` |

**作用范围与取值优先级**

- Nuxt 前台品牌强调部分优先使用用户主色；未设置或颜色值无效时，使用前台默认值 `#ee2b7f`。
- 用户主色通过统一主题变量 `--primary` 提供，可用于主按钮、激活菜单、选中态、链接及局部装饰；页面不应另写一套固定品牌色与用户偏好竞争。
- 基础背景、正文、标题、弱化文字、常规边框和阴影仍使用基础主题层，不能随用户主色整体染色。
- 成功、警告、错误等状态继续使用全系统语义色，不能被用户主色覆盖；例如选择琥珀橙不代表所有警告色也随之改变。
- 主色衍生的浅背景、强调边框、悬停态应从有效主色统一派生，不允许各页面散落固定的粉色、绿色或蓝色值。

**暗色模式**

- Nuxt 前台在日间、夜间和跟随系统模式下均保留用户主色，包括默认粉色，不强制切换成蓝色。
- 这只允许覆盖品牌强调部分；暗色背景、文字和常规边框仍必须遵守蓝灰基础主题。
- 不允许将用户主色扩展成大面积高饱和底色，也不允许同时保留另一套固定绿色或蓝色作为竞争性的主强调色。
- 主色用于按钮背景或文字时，应检查两种主题下的对比度，不应默认任意自定义颜色都适合搭配白字。普通文字对比度应至少达到 `4.5:1`，大号文字至少达到 `3:1`；必要时调整前景色或衍生色，但不改写用户保存的原始颜色。

**保存与恢复**

- 主色偏好通过当前浏览器的 `mint-primary` Cookie 保存，有效期为一年，刷新后继续使用；不表示跨设备或账号同步。
- 点击快捷色块与使用调色盘更新同一份主色偏好，选中的预设应有明确标记，并支持键盘操作。
- 自定义颜色不匹配任何预设时，不标记任何预设为选中。
- 「仅恢复主色与页脚默认值」将主色恢复为 `#ee2b7f`，并恢复显示页脚，不重置主题模式或语言。

以上为 Nuxt 前台的目标约束；新增快捷色块并不代表现有页面的硬编码颜色、衍生色和对比度已全部完成治理。

## 六、暗色模式统一规则

暗色模式是全系统统一规则，不是每个业务域各自定义。

### 必须遵守

- 背景统一使用蓝灰底盘
- 主文字统一使用浅灰白层级
- 常规边框统一使用低对比蓝灰边框
- 系统推荐主强调色优先落在蓝色范围；Nuxt 前台按第五节保留个性化主色，但不能改变蓝灰基础底盘。

### 尽量避免

- 大面积使用绿色作为主视觉
- 同一页面混用高饱和蓝、绿、红三种主强调色
- 延续日间模式的高亮描边和高明度装饰
- 用纯白大面积铺底

### 允许保留

- `warning` 的橙色
- `error` 的红色
- `accent` 的紫色
- 局部高亮用白色

### Blog 前台暗色细则

以下固定蓝色值适用于 `blog-surfer/home`、`blog-surfer/article/:id` 等采用系统推荐配色的阅读场景。Nuxt 前台复用其中的基础背景、文字和常规边框规则；标签、链接、引用边线等品牌强调部分按第五节使用有效主色及其衍生色，不强制使用下列蓝色值。代码语法高亮等非品牌颜色不属于用户主色覆盖范围。

- 卡片背景：`#2C333E` 或 `rgba(44, 51, 62, 0.88)`
- 卡片边框：`#334155`
- 标签背景：`rgba(83, 157, 253, 0.10)`
- 标签文字：`#539DFD`
- 链接色：`#539DFD`
- 阅读区标题：`#F8FAFC` / `#E2E8F0`
- 行内代码背景：`rgba(83, 157, 253, 0.10)`
- 引用块边线：`#539DFD`
- 代码块背景：`linear-gradient(145deg, #111827, #1E293B)`

Blog 前台从日间切暗色时，优先做如下映射：

| 日间颜色 | 暗色替换 |
| --- | --- |
| `#3ECF9A` | `#539DFD` |
| `#15956B` | `#3B82F6` |
| `rgba(62, 207, 154, 0.10)` | `rgba(83, 157, 253, 0.10)` |
| `rgba(62, 207, 154, 0.18)` | `rgba(83, 157, 253, 0.18)` |
| `#0D3D2D` | `#F8FAFC` |
| `#49695D` | `#CBD5E1` |
| `#60786E` | `#94A3B8` |

## 七、组件使用规则

### 全系统公共组件

例如：

- 按钮
- 输入框
- 表格
- 抽屉
- 弹窗
- Tabs
- 面包屑
- 页头
- 空状态

统一规则：

- 优先使用基础主题层
- 状态反馈统一使用全系统语义色
- 不在组件内部直接绑定 `Blog`、`System`、`MES` 的品牌色

### 业务页面中的强调元素

例如：

- 页面主按钮
- 活跃菜单
- 标签选中态
- 页面 Hero
- 模块标题强调块
- 页面装饰渐变

统一规则：

- 这些元素可以使用业务域强调色
- 但只能替换强调部分，不能反向改基础主题层

## 八、后续新增业务域怎么做

如果后续新增 `MES`、`CRM`、`OA`、`WMS` 等业务域，统一按下面步骤扩展：

1. 先复用全系统基础主题层
2. 复用全系统语义色
3. 新增该业务域自己的强调色
4. 暗色模式仍然回归蓝灰底盘

不要这样做：

- 新业务域重新定义整套背景、文字、边框、状态色
- 为新业务域单独做另一套暗色底色系统
- 每个页面都自己写一套颜色规则

## 十、落地检查清单

每次新增页面、组件或主题变量前，先检查：

1. 这次要改的是基础主题层，还是业务域强调层。
2. 如果是背景、文字、边框、阴影，是否错误地写到了业务域里。
3. 如果是主按钮、激活态、标签强调色，是否应该用业务域强调色。
4. 暗色模式是否回到了蓝灰底盘。
5. 是否错误地为某个模块重新定义了整套语义色。
6. 是否在页面里散落大量硬编码十六进制颜色。
7. Nuxt 前台的品牌强调是否使用有效用户主色，而不是残留固定粉色、绿色或蓝色。
8. 快捷预设与自定义调色盘是否更新同一份偏好，恢复默认是否仍为 `#ee2b7f`。
9. 日间与暗色下，主色文字、按钮及选中态的对比度是否满足要求，基础主题与语义色是否保持独立。

## 十一、最终结论

- 你现在需要的不是一个 `blog-surfer` 专用色板，而是一套全系统可扩展主题规范
- 最合适的做法是把主题拆成 `基础主题层 + 业务域强调层`
- `Blog`、`System`、未来 `MES` 都共用同一套基础主题
- 不同业务域只补自己的强调色，不重定义整套底色和语义色
- 暗色模式下，整个系统尽量统一为蓝灰基调，避免每个模块各用一套高饱和主色
