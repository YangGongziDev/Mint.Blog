# Mint.Blog.Vue 后台业务拆分迁移执行方案

- 编制日期：2026-10-12
- 来源项目：Mint.Blog.Vue
- 目标项目：Mint.Blog.Admin.Vue
- 状态：源码调查完成，本文为待执行方案；本次未迁移业务代码，也未执行业务联调。

## 1. 目标与范围

将旧 Vue 项目的博客后台业务迁入独立管理端，复用新管理端的布局、登录认证、动态路由、菜单、权限及请求封装。首轮保持既有业务行为和 Markdown 内容格式，完成后再退出旧后台入口。

业务数据使用现有 WebApi 真实接口，不重新引入 mock 插件、请求拦截器或静态数据冒充业务保存。新管理端已有 system/config、system/file 等静态演示页面保持独立，不替代博客设置、图片对象管理或画廊。

本次范围包括：概览、文章及草稿、分类、标签、专栏、评论、友链、图片资源、画廊、博客设置，以及必要的编辑器、图片选择器、接口、类型和导航适配。

系统登录、用户、角色、权限和个人中心优先复用目标实现，逐项核对旧功能差异，不整体搬入旧认证与系统框架。旧系统菜单页当前是占位页面，不作为已完成业务迁移。旧关于页与目标关于页合并必要信息即可，不新增重复入口。

旧前台继续可用；本方案不包含将旧前台迁往 Next.js，也不要求重构后端 DDD 结构。

## 3. 页面迁移映射

旧页面以 `Mint.Blog.Vue/src/views/blog/admin/` 为基准；目标页面以 `Mint.Blog.Admin.Vue/src/views/blog/` 为基准。下表目标路径为规划，尚未创建。

| 旧文件 | 目标文件 | 新路由 | 必须保留的行为 |
| --- | --- | --- | --- |
| home.vue | dashboard/index.vue | /blog/dashboard | 统计卡片、PV、文章发布趋势 |
| article.vue | article/index.vue | /blog/article | 查询、置顶、可见性、删除与恢复、草稿入口、前台预览 |
| article-create.vue | article/create.vue | /blog/article/create | 校验、封面、Markdown、草稿、发布 |
| article-edit.vue | article/edit.vue | /blog/article/edit/:id | 详情回填、草稿恢复、修改保存 |
| category.vue | category/index.vue | /blog/category | 分类增改删、排序、筛选 |
| tag.vue | tag/index.vue | /blog/tag | 标签增改删、排序、筛选 |
| column.vue | column/index.vue | /blog/column | 封面、发布、置顶、排序、目录树、文章绑定 |
| comment.vue | comment/index.vue | /blog/comment | 查询、审核、审核原因、删除 |
| friend.vue | friend/index.vue | /blog/friend | 增改删、状态、置顶、排序 |
| image.vue | image/index.vue | /blog/image | 桶、公私有、上传、移动、重命名、引用检查、删除 |
| gallery.vue | gallery/index.vue | /blog/gallery | 分类、本地/外链图片、上传、元信息、排序 |
| blog-settings.vue | settings/index.vue | /blog/settings | 站点、作者、头像、社交链接、评论与主题设置 |

目标组织建议：

```text
src/
  api/blog/                 # 按领域迁入服务，调用目标 request
  types/blog/               # DTO、分页、枚举、上传结果
  components/blog/
    ArticleEditor/index.vue # 新建、编辑共用
    ImageSelector/index.vue # 封面、正文等复用
  views/blog/               # 上表业务页面
```

API 按 article、article-draft、category、tag、column、comment、friend、dashboard、setting、image、gallery、file 划分。只抽取确有复用的能力，不提前建设通用业务 CRUD 框架。文件上传服务目前没有独立后台列表页，不新增没有后端支持的附件管理页。

## 4. 基础契约适配

### 4.1 登录与权限

1. 保留目标认证 store、token 存储及并发 401 刷新机制，不迁入旧 Axios、旧认证 store 或旧登录路由。
2. Blog 路由配置 `requiresAuth`，并按后端现状限制 `ROLE_ADMIN`、`ROLE_SUPER`。父路由与可直接访问的子路由都要验证授权。
3. 后端 Blog 权限当前依赖管理员角色；不得只添加前端 `blog.article.*` 权限码，就认为已实现细粒度服务端授权。若扩展该能力，另列前后端和权限数据变更任务。
4. 旧路由 `public: true` 在旧守卫中表示需要登录，不能按字面映射成免登录。
5. 新建、编辑文章隐藏菜单，关联文章列表选中状态。目标 Sidebar 当前按实际路径选中菜单，需接入 `activeMenu` 的消费逻辑；同时明确隐藏页是否创建 tab。
6. 核对旧个人中心资料修改、密码修改与目标能力的差异；缺失的必要能力复用现有后端补齐，避免产生第二套身份体系。

### 4.2 响应、分页与错误

后端响应包含 `success/data/errorCode/message/code`，目标 request 返回完整响应 body。业务 API 读取 `response.data`，不要再次套旧 `{ data, error }` 包装。

博客分页使用 `items/pageNumber/pageSize/totalCount`，ProTable 使用 `current/pageSize` 请求和 `data/total/success` 返回。每个页面显式映射筛选字段、日期和排序：

```ts
const response = await getArticlePageList({
  pageNumber: params.current ?? 1,
  pageSize: params.pageSize ?? 10,
  title: params.title,
});
return {
  data: response.data.items,
  total: response.data.totalCount,
  success: response.success,
};
```

不要继续复制多种历史字段兼容分支；按控制器实际 DTO 收敛类型。失败时保留表单及编辑内容，展示服务端业务消息；不得在失败分支更新列表或显示保存成功。

long ID 序列化为字符串，文章、分类、标签、专栏等 ID 全程保持 string，不转 Number。对象大小等 long 字段也需按 wire 类型处理，展示时明确字节与 MB 换算。

### 4.3 上传与对象生命周期

| 用途 | API（相对 /api） | FormData 字段 | 返回 data |
| --- | --- | --- | --- |
| 博客图片 | /blog/admin/image/upload | newImageFile、newImageOriginalName；可选 bucketName、oldImageName | { url } |
| 博客附件 | /blog/admin/file/upload | newFile、newFileOriginalName；可选 oldFileName | { url } |
| 系统文件 | /file/upload | file | SysFile |

- 使用共享请求体系或 ProUpload 的 customRequest，统一 token、刷新、进度、失败回调。
- FormData 不继承默认 JSON Content-Type，由浏览器/Axios 设置 multipart boundary；上传超时及大小限制以实际服务端配置为准。
- 图片、附件单个删除为 POST，body 是 JSON 字符串；图片批量删除 body 为字符串数组。
- 批量删除结果包含 `deletedCount/skippedUsedCount`，明确告知因引用而跳过的数量。
- 批量移动先预检冲突，再由用户决定覆盖；不默认覆盖同名对象。
- 图片替换采用“上传新图→保存业务→按引用规则清理”顺序。后端传入 oldImageName 时存在先删旧图再上传的流程，不默认传入以免上传失败损失旧资源。
- 画廊是业务记录，上传得到 URL 后仍须保存画廊记录；图片对象管理与画廊不能合为同一张表。

## 5. 接口迁移清单

下表省略统一前缀 `/api/blog/admin`。实现时逐项核对旧服务参数和控制器签名，不把不同模块机械统一成相同 CRUD。

| 领域 | 已有主要接口 | 特殊约束 |
| --- | --- | --- |
| 文章 | GET/POST /article；GET/PUT/DELETE /article/{id}；PATCH /top、/visibility | DELETE 带命令 body；visibility 1=公开，2=仅专栏可见 |
| 草稿 | GET/POST /article-draft；GET/DELETE /article-draft/{id}；GET /by-article/{articleId}；POST /{id}/publish | 按文章查询可返回 data:null；已有草稿发布前先保存 |
| 分类 | GET /category、/category/page；POST/PUT/DELETE；PATCH /sort、/sort/first、/sort/last | 全量选项与分页接口分开；保留 deleteType |
| 标签 | GET /tag、/tag/page；POST/PUT/DELETE；PATCH 排序 | 与分类分别维护类型和 API |
| 专栏 | GET/POST /column；PUT/DELETE /column/{id}；GET/PUT /{id}/catalog；PATCH /publish、/top、/sort | 目录 children、level、articleId 需完整保存 |
| 评论 | GET /comment；PATCH /{id}/examine、/{id}/delete | 无通用新增/编辑接口；删除不是 DELETE |
| 友链 | GET/POST /friend；PUT /{id}；PATCH /top、/status、/sort、/sort/first、/sort/last、/delete | 状态枚举不与评论混用 |
| 概览 | GET /dashboard/statistics、/pv-statistics、/publish-article-statistics | 接真实指标，保留日期与图表语义 |
| 博客设置 | GET/PUT /setting | 强类型对象，不复用 system/config 键值表 |
| 画廊 | /gallery/categories、/categories/options、/images 及按 ID 修改删除 | 本地与外链两种来源；查重当前仅覆盖已加载数据 |
| 图片 | /image；/image/buckets；/upload、/delete、/delete-many、/rename、/move、/move-many/precheck、/move-many | 桶名编码、引用保护、移动冲突、不同排序枚举 |
| 附件 | POST /file/upload、/file/delete | 当前没有附件列表接口 |

文章删除类型保留 `1=逻辑删除、2=物理删除、3=恢复`。Axios DELETE 的 body 放入 `config.data`。评论删除使用 `{ id, deleteType }`，友链使用 `{ friendId, deleteType }`，不得随意改字段。

控制器依据：[Blog Admin 控制器目录](../Mint.Blog.WebApi/Controllers/Blog/Admin/)、[图片控制器](../Mint.Blog.WebApi/Controllers/Blog/Admin/Uploads/ImageController.cs)。

## 6. 文章编辑器专项

首轮保留 md-editor-v3 和 Markdown 存储格式，迁入所需依赖及样式，将 UI 组件、图标和主题接入目标项目。暂不直接替换成输出 HTML 的 Editor。

必须逐项迁移：

- 标题、正文、摘要、封面、分类、标签回填与校验；保留标题 60 字符、摘要 160 字符等原约束并核对后端规则。
- 从正文选封面、本地封面上传、从 RustFS 选择已有图片。
- 正文插图的临时 blob URL、待上传 File 映射、保存前上传及 URL 替换。
- 服务端草稿列表、读取、按文章恢复、保存、发布、删除。
- 本地草稿失败兜底，以及离开编辑页时的未保存内容保护。
- 保存失败只清理本轮新上传且可清理的资源，不删除旧文章引用资源；清理失败保留可诊断信息。

现有实现的边界不得被误写为已实现功能：

- 本地草稿不是已完成的定时自动保存；File 未随 JSON 持久化，刷新后 blob 图片恢复有限制。
- 保存进度里的移除图片数量不代表旧图片已经删除。
- 独立 origin 的 localStorage 不共享；切换前提示处理未保存草稿。服务端草稿按原账号验证可访问性，本地草稿如需跨站转移另做显式导出导入。

若后续统一 Milkdown，需另行验证旧 Markdown 往返保存、异步详情回填、草稿回填和图片生命周期，再决定替换。

## 8. 旧项目保留与清理规则

不得直接删除旧 `service/blog/admin` 或整个 system 目录。

| 内容 | 处理方式 |
| --- | --- |
| admin/gallery.ts 中前台函数和共享 DTO | 先迁到 surfer 服务或共享类型，再修正前台画廊引用 |
| service/axios.ts、认证相关依赖 | 前台仍使用，保留；后台退出后另按引用收敛 |
| store/system 中 app/theme/route/tab 等 | 前台仍有依赖，逐文件核对 |
| layouts/frontdesk、前台 views/components/service/store/router/menu | 保留并回归 |
| 通用组件、hooks、locales、utils、system assets | 按实际消费者判断，不能按目录名批量删除 |
| 旧后台页面、后台专用组件及菜单路由 | 新端验收、引用清零后删除 |
| md-editor-v3 | 旧 src 当前仅后台编辑器引用，迁出后复核再移除 |
| ant-design-vue、图标、echarts、vueuse、highlight.js | 前台仍使用，不能随后台整体移除 |

尤其保留旧前台 footer 使用的 system SVG 头像、文章和专栏使用的日期工具。旧入口清理后运行构建并检查动态路由、菜单聚合与启动校验，不能只检查静态 import。

## 9. 验证与验收

### 自动检查

在目标项目执行：

## 10. 部署切换与回退

1. 先部署新管理端到独立可验证地址，旧入口保留，完成真实业务验收。
2. 配置正确 API 基址与 `/api` 前缀；目标生产配置当前含占位地址，不能原样发布。
3. 配置新管理端 SPA fallback、跨域策略和前后台站点地址，验证直接访问文章编辑 URL。

6. 最后移除旧后台专用源码。回退部署不等于回退业务写入；迁移期间的新写入仍由共用后端保存。
